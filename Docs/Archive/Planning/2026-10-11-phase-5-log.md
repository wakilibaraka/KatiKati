## Addendum 2 — Accessibility granted: gaps proven and fixed
- **Gap 1 (5b, proven):** SIGTERM/SIGINT killed the process outright (no signal handlers), so `applicationShouldTerminate`/`stopAndRestore` never ran and a lifted window stayed lifted (Finder 0,38,1710x1074 native -> stuck at 1018 tall). AppleEvent quit with a lifted window restores in ~1s (control).
- **Gap 2 (5c/C3, proven):** `kill -9` with a lifted window left it displaced and a relaunch did not restore it (lift sessions were memory-only).
- **Fixes:** `AppDelegate.installTerminationSignalHandlers` routes SIGTERM/SIGINT to `terminate:` via a runloop perform (calling it inside the GCD handler deadlocked `stopAndRestore`, observed: hung >30s). New Core `WindowLiftRecovery` (+4 tests) mirrors pending lifts to `Application Support/com.katikati.app/window-lift-recovery.json`; `WindowLiftAvoidanceController.persistRecovery()/loadRecoveredRestorations()` replay them at start through the existing `restoreOne` (re-checks process start time, window liveness, still at lifted frame). Clean quit deletes the file.
- **Verified live:** kill -9 with lifted Finder window -> relaunch -> window back to 1074 tall, file removed. AppleEvent quit with lifted window -> restored, file removed. SIGTERM/SIGINT with **no** lifted window -> exit in ~1s.
- **NOT re-verified live:** SIGTERM/SIGINT with a lifted window after the deadlock fix (could not re-create a lifted window deterministically via scripting). Same code path as the verified AppleEvent quit; owner to confirm: maximize a window, wait for lift, `kill -TERM $(pgrep -x KatiKati)`.
